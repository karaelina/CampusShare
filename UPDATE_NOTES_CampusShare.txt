CampusShare Update Notes

This update adds the following prototype workflow improvements:

1. Provider Add Equipment now requires a Designated Pickup / Use Location.
2. Student rental request displays the provider-designated location as read-only; the student cannot choose a different location.
3. Rental requests save student identity, provider identity, dates, pickup/use location, payment method, total, and status in campusShareRentals.
4. Admin can approve a Pending rental request only. Once approved, the admin sees a note that the provider manages pickup and return tracking.
5. Provider Rental Requests shows student/rental/payment/location details. Provider can mark an Approved rental as picked up (Active), then mark an Active rental as returned (Completed).
6. Provider Active Rentals and Returns include the student and designated location details.
7. Student My Rentals is tracking-only and no longer changes rental status itself.

Prototype limitation: this version still uses browser localStorage. Data is shared only among pages in the same browser/profile on the same device. It is not a shared multi-device database and should be treated as a demonstration, not a production booking/payment system. Older equipment records may not have a designated location; they display a fallback until the provider edits/re-adds the equipment.
